# Phase 2 simulation

The CEO-only workflow records projects, task assignments, dependencies, simulated transitions and approvals in PostgreSQL. The simulation changes only database state; it does not run employees, invoke providers, modify GitHub, deploy or execute code. No sample projects are seeded. Project archive is reversible and preserves history. Actions are submitted to `/api/workflow` with JSON and a matching Origin; the existing session middleware protects the endpoint. The command schemas define supported operations. Task and project edits and approval decisions use versions to reject stale writes. Project-level transaction locks serialize graph validation and transitions. Dependencies may only change while the dependent task is draft. In-progress and done transitions require completed dependencies and all existing project approvals to be approved. Audit records label the CEO actor and simulation mode.

Run `npm run db:migrate` after updating the checkout, followed by `npm run db:seed`. Run `npm run test:integration` against a disposable database and `npm run test:e2e` with the test-only credentials described in the README. Existing Phase 1 security limitations still apply; see [security review](security-review.md). The audit table is append-only through the application API, but PostgreSQL owners can alter it; production needs database privilege separation and a retention policy. No customer projects are created by setup or tests.

The workflow screen shows up to 100 projects, 200 tasks, 500 dependencies, 100 approvals and 100 recent events; API list pagination is available for projects, tasks and approvals. Large datasets need a paginated UI. The full six-role acceptance scenario and concurrent mutation races need additional end-to-end coverage before considering Phase 2 complete. A rejected approval currently remains a blocking gate; a reviewed supersession workflow is still needed.
